# HEVC-720p 后续候选评估（未合入）

## 结论

在整数双向预测融合（优化点 8）之后，又并行评估了三条路径。三者均未达到
“CPU cycles 稳定下降”的合入门槛，因此不生成正式代码补丁，也不占用后续
patch 编号。

测试基线为优化点 8，使用 `-threads 0`，固定 CPU 0～31，并通过
`perf stat -e task-clock,cycles,instructions` 采集 PMU 数据。

## 1. 直接双向平均核循环展开

`ff_hevc_put_hevc_pel_bi_direct_8_neon` 在优化点 8 后约占 9.2% CPU。完整片源
的调用分布为：

| 块尺寸 | 调用次数 | 占比 |
|---|---:|---:|
| 16×16 | 18,979,345 | 63.52% |
| 32×32 | 9,302,740 | 31.13% |
| 8×8 | 1,596,100 | 5.34% |

候选将对应 NEON 循环展开为四行，并为非四倍数高度保留两行尾部。完整 CRC 和
`checkasm-hevc_pel` 均通过，但 11 对交替测试中：

- instructions 降低 0.62%；
- task-clock 配对中位数上升 0.23%；
- cycles 配对中位数上升 0.23%；
- real 基本持平。

该核已经接近两次加载、一次 `URHADD`、一次存储的带宽下限。减少循环控制指令
没有转化为周期收益，候选被否决。

## 2. 相同参考画面和相同 MV 快速路径

完整 14997 帧统计结果：

- 双向预测占全部 inter PU 的 72.823%，占 inter 像素的 74.667%；
- 双向预测中 `mv0 == mv1` 占块数 91.811%、像素 92.090%；
- L0/L1 最终解析到同一参考画面的安全命中数为 0。

L0 和 L1 是两套独立参考列表，`ref_idx[0] == ref_idx[1]` 不代表同一参考画面。
若只比较索引，本片会错误命中约 977.6 万个实际引用不同画面的块。安全条件的
命中率为零，增加判断只会产生开销，因此未实现正式补丁。

## 3. 双水平分数像素滤波融合

该候选在两路参考均为水平分数像素时，直接计算两路滤波结果并合成最终 8-bit
像素，绕过 `lc->tmp`。热点命中量为：

| 路径 | 块数 | 像素数 |
|---|---:|---:|
| Luma qpel 32×32 | 442,917 | 453,547,008 |
| Chroma epel 16×16（两平面调用口径） | 1,333,054 | 341,261,824 |

最终原型采用：

- qpel：i8mm `USDOT`，在 32-bit accumulator 层合并两路卷积，仅执行一次
  `ADDP/TRN/SQXTN`；
- epel：普通 NEON 四抽头计算，两套绝对值系数常驻寄存器；
- 仅在 AArch64、8-bit 且运行时支持 i8mm 时启用，其他架构保持原路径。

正确性结果：

- `checkasm-hevc_pel` 349/349 通过；
- 完整 14997 帧 `framecrc` 文本 SHA-256 为
  `b32a73512313062dd115911a0adfba24280292baf0404e5e05012ee3f11d1449`，
  与优化点 8 基线一致。

15 对固定 CPU 交替测试的配对结果：

| 指标 | 配对中位变化 | 胜出次数 |
|---|---:|---:|
| real | -1.118% | 12/15 |
| task-clock | -0.052% | 10/15 |
| cycles | -0.040% | 8/15 |
| instructions | -0.202% | 15/15 |

虽然指令数稳定下降，但 cycles 几乎持平且仅 8/15 胜出，没有达到预设的
“cycles 配对中位数至少下降 0.3%、至少 9/15 胜出”门槛，因此不合入。
