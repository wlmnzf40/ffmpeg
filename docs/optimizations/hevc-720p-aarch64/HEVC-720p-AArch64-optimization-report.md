# FFmpeg 7.1.1 HEVC-720p 鲲鹏 920B 优化报告

## 结论

在同一台 256 逻辑核鲲鹏 920B 上，使用同一个 15000 帧输入和
`-vf format=rgb24 -f null` 命令：

| 版本 | real 平均 | user 平均 | 相对墙钟性能 |
|---|---:|---:|---:|
| 原 BoostKit OpenMP RGB24 | 2.113 s（5 轮） | 325.08 s | 1.00× |
| 最终 NEON + HEVC threads + PGO/LTO | 1.082 s（3 轮） | 21.78 s | 1.95× |

最终版本单次最好为 1.055 s，对应单次超过 2×；但稳定平均值为 1.95×，因此
不能宣称已稳定达到 2.00×。CPU 总耗时下降约 14.9×。

## 测试环境

- CPU：Kunpeng 920 7270Z，2 socket，128 物理核/256 逻辑核；
- OS：openEuler 22.03 LTS-SP3；
- GCC：10.3.1；
- 输入：HEVC Main、1280×720、25 fps、15000 帧；
- 输出路径：解码后转换为 RGB24，写入 null muxer；
- CPU governor：performance，约 2.9 GHz。

## 优化序列

1. 增加 AArch64 `yuv420p → rgb24` NEON 分派和 `st3` 内核。
2. 利用 YUV420 垂直 2:1 抽样，两行共享一次色度计算。
3. 仅对 HEVC 将自动 frame-thread 上限从 16 提到 32。
4. 使用 `tsv110` 定向 PGO 和并行 LTO 构建。

每个优化点的调用路径和代码细节见同目录的独立走读报告。

补丁位于 `patches/hevc-720p-aarch64/`，编号即应用顺序；每个文件只包含一个
优化提交。四份补丁可从 FFmpeg 7.1.1 基线顺序应用，也可直接检出包含相同四个
提交的分支。

## 正确性门禁

- 最终 RGB24 与 FFmpeg 原有 RGBA NEON 去掉 alpha 后逐字节一致；
- 旧版与最终版前 100 帧原生 YUV420 MD5 完全一致；
- RGB24 NEON 相对通用 C 的差异不超过既有 RGBA NEON 舍入范围：最大 3，
  PSNR 46.931 dB；
- 汇编和线程改动均已在 AArch64 服务器完成编译、15000 帧运行和多轮性能测试。

## 性能数据说明

benchmark 只有约一秒，容易受共享机调度影响。报告同时保留多轮平均值和单次
最好值，并以平均值作为结论。旧版/新版交叉跑会使旧版的 150 核级 OpenMP
负载影响紧随其后的新版，因此最终值采用无并行编译负载的新版本独立三轮。

X86 服务器在本次测试期间 SSH 持续超时，未重新采集跨机器对比；本报告中的
提升倍数全部来自同一台 ARM 机器、同一输入、同一命令的前后对比。

## 后续空间

perf 中剩余主要热点是 `ff_hevc_deblocking_boundary_strengths`（约 16% cycles）
和 HEVC 环路滤波/运动补偿。继续追求稳定 2×，应优先为边界强度计算设计独立
正确性测试后再做数据布局或 SIMD 优化；直接跳过 deblock 会改变解码输出，不应
作为有效优化提交。
